#### Fix range formatting expanding to a non-source-element node (#19880 by @Kjubikstronk)

When the range landed inside a callback body, the expanded range could cover an
expression rather than a statement, which printed as a standalone element and
gained a trailing semicolon. Ranges landing in an object or class method threw
`Missing semicolon` instead.

<!-- prettier-ignore -->
```jsx
// Input (range covers the two indented lines)
beforeEach(() => {
  // c
  a();
});

// Prettier stable
beforeEach(() => {
  // c
  a();
};);

// Prettier main
beforeEach(() => {
  // c
  a();
});
```
