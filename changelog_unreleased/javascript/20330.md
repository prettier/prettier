#### Fix unstable unary operands with leading comments (#20330 by @ZXLyyds100)

Removing redundant parentheses around a commented member or call operand could
make a unary expression require a second formatting pass. The first pass now
uses the same wrapping as the second pass.

<!-- prettier-ignore -->
```js
// Input
delete (/** @type {any} */ window).__pwned;
typeof (/* comment */ object).property;

// Prettier stable (first pass)
delete /** @type {any} */ window.__pwned;
typeof /* comment */ object.property;

// Prettier stable (second pass)
delete (/** @type {any} */ window.__pwned);
typeof (/* comment */ object.property);

// Prettier main (first and second pass)
delete (/** @type {any} */ window.__pwned);
typeof (/* comment */ object.property);
```
