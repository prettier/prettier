#### Fix range formatting inside a `for` statement head (#20163 by @ump45nose)

Formatting a range that only covers the head of a `for…of`/`for…in` statement
re-parsed the fragment on its own, appended a `;`, and returned code that no
longer parses. The range now falls back to the whole statement.

<!-- prettier-ignore -->
```js
// Input
for (const f of filters) {}

// Prettier stable (--range-start 5 --range-end 12)
for (const f; of filters) {}

// Prettier main
for (const f of filters) {}
```
