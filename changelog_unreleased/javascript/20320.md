#### Fix unstable formatting of method chains with expandable object arguments (#20320 by @smg99)

Prettier now keeps a method chain expanded when its last call argument breaks across lines. This prevents the chain from collapsing on a second formatting pass when an object argument needs multiple lines (for example at `--print-width 100`).

<!-- prettier-ignore -->
```jsx
// Input
async function a(harness, firstPatch) {
  harness.deps.patchDraft.mockReturnValueOnce(firstPatch).mockResolvedValueOnce({ ok: true, status: 200, body: { revision: 20, changed: ['span_a'], plan_name: 'orm' } });
}

// Before (first pass)
async function a(harness, firstPatch) {
  harness.deps.patchDraft
    .mockReturnValueOnce(firstPatch)
    .mockResolvedValueOnce({
      ok: true,
      status: 200,
      body: { revision: 20, changed: ["span_a"], plan_name: "orm" },
    });
}

// Before (second pass)
async function a(harness, firstPatch) {
  harness.deps.patchDraft.mockReturnValueOnce(firstPatch).mockResolvedValueOnce({
    ok: true,
    status: 200,
    body: { revision: 20, changed: ["span_a"], plan_name: "orm" },
  });
}
```

The corrected output keeps the expanded chain shown in the first pass on subsequent passes too.

This also applies when the expanded object or array follows other arguments:

<!-- prettier-ignore -->
```js
// Input
request.getLogger().debug('message', {...fields, context: 'vvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvv'});

// Output (stable on subsequent passes)
request
  .getLogger()
  .debug("message", {
    ...fields,
    context: "vvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvvv",
  });
```
