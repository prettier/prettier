#### Keep comments inside parenthesized type casts (#20493 by @manav4u)

Leading comments in parenthesized `as` and `satisfies` expressions used as a member object or call target are now kept inside the parentheses. This fixes a case where formatting twice moved the comment away from the expression it describes.

<!-- prettier-ignore -->
```tsx
// Input
const f = async () => ((
  // comment
  await foo()) as T).value;

// Prettier stable (first pass)
const f = async () =>
  (
    // comment
    (await foo()) as T
  ).value;

// Prettier stable (second pass)
const f = async () =>
  // comment
  ((await foo()) as T).value;

// Prettier main (both passes)
const f = async () =>
  (
    // comment
    (await foo()) as T
  ).value;
```
