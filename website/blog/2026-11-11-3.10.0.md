We're excited to announce Prettier 3.10!

This release adds support for new Flow syntax and the latest JavaScript proposals, and introduces a new official plugin — [`@prettier/plugin-yuku`](https://github.com/prettier/prettier/tree/main/packages/plugin-yuku) — powered by the high-performance Yuku toolchain, with dedicated JavaScript and TypeScript parsers.

It also includes a wide range of fixes and improvements across JavaScript, TypeScript, Markdown, HTML, and more.

If you find Prettier valuable, please consider [sponsoring us on OpenCollective](https://opencollective.com/prettier) or supporting the upstream projects we rely on. Your contributions help us keep improving the tool for everyone.

Thank you for your continued support! ❤️

## Highlights

### JavaScript

#### Added a new official plugin `@prettier/plugin-yuku` ([#19628](https://github.com/prettier/prettier/pull/19628), [#19629](https://github.com/prettier/prettier/pull/19629) by [@fisker](https://github.com/fisker)) {#change-19629}

`@prettier/plugin-yuku` is powered by [Yuku](https://yuku.fyi/) (A high-performance JavaScript/TypeScript compiler toolchain written in Zig).

This plugin includes two new parsers: `yuku` (JavaScript syntax) and `yuku-ts` (TypeScript syntax).

**To use this plugin:**

1. Install the plugin:

   ```bash
   yarn add --dev prettier @prettier/plugin-yuku
   ```

2. Add it to your `.prettierrc`:

   ```yaml
   plugins:
     - "@prettier/plugin-yuku"
   ```

Due to package size limitations, this plugin is not bundled with the main prettier package and must be installed separately.

For more information, check [the package homepage](https://github.com/prettier/prettier/tree/main/packages/plugin-yuku).

Big thanks to [@arshad-yaseen](https://github.com/arshad-yaseen) for his excellent work.

### Flow

#### Support new Flow syntax ([#20136](https://github.com/prettier/prettier/pull/20136) by [@gkz](https://github.com/gkz)) {#change-20136}

Prettier now supports Flow syntax added in `flow-parser` 0.332.0, including template literal and constructor types, mapped-type modifiers and key remapping, abstract and override class members, inline import types, CommonJS import/export bindings, and `unique symbol` types.

<!-- prettier-ignore -->
```flow
// Input
abstract class Example { abstract value:string; }
type Constructor = new <T>(value:T)=>Container<T>;
type Getters<T> = {-readonly [K in keyof T as `get${K}`]-?: T[K]};
type Imported = import("package-name").Exported;
type Unique = unique symbol;
import Value=require("value-module");
export = Value;

// Prettier 3.9
// Not supported

// Prettier 3.10
abstract class Example {
  abstract value: string;
}
type Constructor = new <T>(value: T) => Container<T>;
type Getters<T> = { -readonly [K in keyof T as `get${K}`]-?: T[K] };
type Imported = import("package-name").Exported;
type Unique = unique symbol;
import Value = require("value-module");
export = Value;
```

#### Support parameter properties, `in out` variance, non-null assertions, `export as namespace`, unlabeled optional tuple members, declared class private fields, and declared class mixin extends in Flow ([#20407](https://github.com/prettier/prettier/pull/20407) by [@gkz](https://github.com/gkz)) {#change-20407}

The `flow` parser can now format constructor parameter properties, `in out` variance annotations, non-null assertions, `export as namespace` declarations, unlabeled optional tuple members, private fields in declared classes, and declared classes that extend a mixin call. Previously, Prettier threw an error on all of these.

<!-- prettier-ignore -->
```flow
// Input
class A { constructor(public x: string, private readonly y: number = 1) {} }
type Invariant<in out T> = {get: () => T, set: (value: T) => void};
const value = maybeNull! .value;
export as namespace Library;
type T = [number ?, (string | boolean) ?];
declare class C { #x; }
declare class D extends mixin( Base ) {}

// Prettier 3.9
Error: Missing visitor keys for 'ParameterProperty', etc.

// Prettier 3.10
class A {
  constructor(
    public x: string,
    private readonly y: number = 1,
  ) {}
}
type Invariant<in out T> = { get: () => T, set: (value: T) => void };
const value = maybeNull!.value;
export as namespace Library;
type T = [number?, (string | boolean)?];
declare class C {
  #x;
}
declare class D extends mixin(Base) {}
```

#### Avoid stack overflows when formatting long binary expressions ([#20409](https://github.com/prettier/prettier/pull/20409) by [@splincode](https://github.com/splincode)) {#change-20409}

Prettier now formats long chains of binary operators without overflowing the JavaScript call stack. Previously, formatting thousands of operands could fail with a `RangeError`.

<!-- prettier-ignore -->
```js
// Prettier 3.9
await prettier.format("a + ".repeat(2000) + "a", { parser: "babel" });
// RangeError: Maximum call stack size exceeded

// Prettier 3.10
await prettier.format("a + ".repeat(2000) + "a", { parser: "babel" });
// 'a +\n' +
//  '  a +\n' +
//  '  a +\n'... 2003 more characters
```

#### Add support for "Structs", "Import Sync", and "Deferred re-exports" proposal ([#20427](https://github.com/prettier/prettier/pull/20427), [#20430](https://github.com/prettier/prettier/pull/20430), [#20430](https://github.com/prettier/prettier/pull/20430), [#20438](https://github.com/prettier/prettier/pull/20438) by [@fisker](https://github.com/fisker)) {#change-20427}

Prettier 3.10 added support for new ES proposals.

- [Structs](https://github.com/tc39/proposal-structs) proposal (Only non-shared structs)

  ```jsx
  struct Point {
    x = 0;
    y = 0;

    get length() {
      return Math.hypot(this.x, this.y);
    }
  }
  ```

- [Import Sync](https://github.com/tc39/proposal-import-sync) proposal

  ```jsx
  const { readFile } = import.sync("node:fs");
  ```

- [Deferred re-exports](https://github.com/tc39/proposal-deferred-reexports) proposal

  ```jsx
  export defer { parse } from "./parser.js";
  ```

  ```jsx
  import { parse, format } as myLib from "my-library";
  export { parse } as parser from "my-library";
  ```

Please keep in mind our [policy on non-standardized syntax](https://prettier.io/docs/en/rationale.html#disclaimer-about-non-standard-syntax) before using these proposed syntax features with Prettier.

#### Share `.editorconfig` reads across `resolveConfig()` calls ([#20462](https://github.com/prettier/prettier/pull/20462) by [@lishaduck](https://github.com/lishaduck)) {#change-20462}

Prettier now caches each parsed `.editorconfig` file and shares it with every other file under it. Previously, each call would probe from the file's directory up to the project root for every potential `.editorconfig`.

In a TypeScript monorepo using a custom formatting script, config resolution for all 786 of their files now reads the `.editorconfig` 31 times instead of 3,969, and is approximately 3× faster.
